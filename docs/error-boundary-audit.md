# 오류 응답 조사 — 2026-10-09

잘못된 입력, 권한 부족, 요청 제한, 요청 취소, 의존 서비스 장애가 일반적인 내부 오류로 바뀌는 경로를 수정했다. 실제 서버 결함과 저장 데이터 불일치는 내부 오류로 유지한다.

## 조사 범위

기준은 `main`의 `d5a5efd`(API 1.6.0)다. 테스트 파일을 제외한 Go 파일 1,357개, 함수 9,560개를 AST로 검색했다. Connect 요청·응답 서명을 가진 함수는 498개다. 이 수에는 내부 서비스 함수도 포함되므로 공개 엔드포인트 수와 같지 않다.

[오류 경계 목록](error-boundary-inventory.csv)은 수정 전 위치를 기록한 2,416개 호출의 목록이다.

| 호출 | 개수 |
| --- | ---: |
| `errs.Internal` | 1,958 |
| `errs.InternalMsg` | 265 |
| `errs.Wrap` | 41 |
| `connect.NewError` | 41 |
| `http.Error` | 111 |

공통 변환 함수, MCP 입력·도구 실행 경계, 분류를 잃을 수 있는 중첩 오류, 직접 작성한 HTTP 500 경로를 검토했다. Connect 핸들러가 일반 오류를 직접 만드는 5곳은 변환 실패, 저장된 테마 손상, 잘못된 애플리케이션 결과 등 서버 불변식 오류였다. 직접 `*connect.Error` 타입 검사만 하는 경로는 41곳이었다. 그 경로가 공통 `Internal`/`Wrap`으로 넘기는 중첩 오류도 새 공통 변환에서 기존 분류를 보존한다.

검색 목록 전체에 대해 운영 장애를 주입한 것은 아니다. 실제 운영 DB·스토리지·메일·권한 서버의 고장 상황을 모두 재현했다는 보장은 제공하지 않는다.

## 확인한 문제와 수정

| 경로 | 기존 문제 | 수정 결과 |
| --- | --- | --- |
| `document_read` | `m=fields`에서 `f`가 없거나, `m=blocks`에서 `b`가 없을 때 JSON-RPC 내부 오류 | 안전한 입력 오류를 `isError=true` 도구 응답으로 전달. 필요한 선택자를 도구 설명과 스키마에도 안내 |
| AI 문서 Open/Describe/Read/Validate/Apply | 문서 식별자·로케일·선택자 검증 실패와 내부 데이터 오류를 구분하지 못함 | 호출자 입력 오류 타입을 구분. Connect Open/Apply에서는 InvalidArgument로 응답 |
| 공통 `Internal`/`Wrap` | 이미 분류된 400·403·404·409·429·503 등이 다시 Internal로 감싸짐 | 오류 체인을 검사해 기존 Connect 코드·메타데이터·상세 정보를 보존 |
| 취소·시간 초과 | 일반 Go context 오류와 MCP OutOfRange가 내부 오류로 처리될 수 있음 | 취소·시간 초과 코드를 보존하고 MCP에는 안전한 안내 반환. OutOfRange도 도구 실패로 전달 |
| UUID DB 입력 | 잘못된 UUID를 쿼리에 전달한 드라이버 오류가 일반 500이 됨 | SQLSTATE 22P02 중 UUID 문법 오류만 InvalidArgument로 변환. 다른 DB 오류는 내부 오류 유지 |
| multipart HTTP 업로드 | 길이만 검사한 `fileId`를 UUID DB 컬럼에 직접 전달 | 인증 후 canonical UUID를 검사해 DB 접근 전에 400 반환 |
| client media HTTP 업로드 | 분류된 인증·요청 제한·의존 서비스 오류를 기본 500으로 변환 | 401·403·404·409·429·503·504·499·501 분류 보존 |
| 이미지 프록시 | 외부 이미지 서비스의 500을 “Image not found”로 표시 | 실제 404와 외부 서비스 장애를 구분. 외부 5xx는 502와 안전한 메시지 |
| 폰트 CSS 프록시 | 외부 500을 그대로 반환하거나 외부 본문 읽기 실패를 내부 500으로 표시 | 외부 5xx와 본문 읽기 실패를 502로 전달 |

MCP에서 일반적인 내부 오류와 손상된 저장 문서는 계속 JSON-RPC `-32603`의 `Internal error`로 처리한다. 내부 경로·DB 메시지를 도구 응답에 노출하지 않는다. 이미지 응답을 이미 전송한 뒤 스트림이 끊긴 경우에는 상태를 다시 바꿀 수 없으므로 서버 로그에 기록한다.

## 유지한 서버 오류

설정되지 않은 문서 저장소·publisher, 손상된 저장 문서·로케일, 잘못된 서버 서명 설정, 실제 DB/스토리지 실패는 입력 오류로 바꾸지 않았다. `gorm.ErrRecordNotFound`나 모든 SQL 제약 오류를 공통으로 404/400으로 바꾸지도 않았다. 호출 경로에 따라 내부 참조 손상일 수 있기 때문이다.

Kratos webhook의 잘못된 본문은 400, 정책 거부는 403/409로 처리하고, 계정 처리 실패는 로그와 정해진 서버 오류 메시지를 남긴다. webhook 실패 상태를 바꾸면 Kratos의 계정 처리 계약도 영향을 받으므로 유지했다.

## 검증

- 실제 인증된 HTTP MCP 요청으로 누락·빈 선택자·혼합 모드·알 수 없는 블록/필드와 권한 거부를 검증했다. 입력 검증은 문서 I/O 전에 끝나며, 내부 오류의 비공개 메시지는 응답에 나오지 않는다.
- 16개 Connect 코드의 중첩 오류, 메타데이터·상세 정보 보존, context 취소·시간 초과, UUID 드라이버 오류의 제한된 변환을 테스트했다.
- 이미지/폰트 외부 404·429·500·503, 외부 본문 읽기 실패와 업로드 HTTP 분류를 테스트했다.
- `go test ./...`: 140개 테스트 패키지 통과. 2개 패키지의 3개 미디어 테스트는 로컬에 `magick`/`ffmpeg`가 없어 실패했다. 해당 패키지의 성공을 주장하지 않는다.
- 마지막 변경 뒤 관련 6개 패키지 테스트, 전체 `go vet ./...`, 서버 빌드 통과.
- PR CI는 ImageMagick과 ffmpeg를 설치하고 전체 테스트·vet·빌드를 수행한다.

## 관련 서비스

Geul Web의 16개 API route도 조사했고, 별도 PR에서 입력 검증·HTTP 오류 분류·세션 장애·미디어 조회 경계를 수정한다. Web 보고서에는 기본값을 반환하는 query 후보 목록과 검증 결과를 기록한다.

OpenDiscogs Cloudflare gateway는 인증 서버 장애와 인증 응답 손상을 503, 요청 제한을 429, 예상하지 않은 redirect를 502로 처리하며 실제 자료 404를 유지한다. 코드를 읽고 기존 실패 테스트를 확인했다. 로컬에 gateway 의존성이 없어 이번 조사에서 gateway 테스트를 다시 실행하지는 않았다.

Go OpenDiscogs API는 공통 응답에서 자료 없음 404, 잘못된 query 400, DB deadline 504, 일반 내부 실패 500을 구분한다. `internal/httpapi`와 `internal/management` 테스트를 실행해 통과했다. OpenDiscogs batch 작업과 폐기된 Java 구현은 이번 HTTP/MCP 응답 조사 범위에 포함하지 않았다.
